## 已證實並修正的缺陷

| 優先序 | 重現證據與影響 | 修復與重測 |
|---|---|---|
| 高 | 原 schema 在 MariaDB 10.4 出現 ERROR 1273 Unknown collation，無法全新安裝 | 全新建表改用 utf8mb4_unicode_ci，真實匯入、中文保存及兩組六關通過 |
| 高 | 大小寫不敏感的掛載檔案系統上，原 Apache 回應 `/api/SEED_CAKE.SQL`、`/TESTS/helpers.mjs` 為 200，可能洩漏題目正解 | .htaccess 使用不分大小寫比對；同一路徑及正常大小寫均重測為 403/404 |
| 中 | 舊学生欄位使用 0900 定序時，訊問遷移出現外鍵不一致（MySQL 3780） | 沿用既有欄位型別／定序，MySQL 兩種及 MariaDB 兩種定序驗證，重跑保留中文資料 |
| 中 | 明確空環境值被 ck_env 忽略，可能回退其他密碼 | 設定讀取區分「未設定」與「空值」；紅綠測試通過 |
| 中 | 原測試硬寫 Mac socket／工具路徑；Apache session 更新產生兩個 cookie，helper 使用舊 cookie 導致 401 | 工具與連線改可配置，使用最後的有效 session cookie；兩套全測通過 |

另外以已知 CRLF/LF 字串驗證 Windows 換行解析，避免測試誤判；不是宣稱已重現原生 mysql.exe 的輸出。影片改用可攜 PHP 複製工具，保留既有檔案且不依賴符號連結。

## QA、安全與補充檢查

從學生角度驗證重登、斷線與時間到保存；從研究者角度驗證分組、兩組資訊界線、36 分、理由／AI 稽核資料及重複遷移；從未授權使用者角度測試未登入、他人學號、跳階段與私有檔案存取。這是自動化測試及 AI 多角度審查，沒有真人專家認證。

PHP 8.2 語法 27 檔、JS 語法 45 檔通過；Git 檔名檢查未發現 Windows 保留名稱、大小寫碰撞或候選符號連結。瀏覽器流程檢查未處理 JS 錯誤。独立唯讀審查提出空密碼／換行／文件指令問題，已處理。沒有現成 build、型別檢查或 CI，不把未配置的工具算成通過。

## 尚未驗證與改善提案

Windows 原生 Apache／PHP／MariaDB、原生 mysql.exe／php.exe、Windows 憑證與防火牆：按 [Windows 指南](../windows-xampp.md) 在目標電腦驗收。

真實 AI 的串供與評語品質、正式 SurveyCake、七支正式影片、正式資料搬移未驗證。先前真實 AI 兩個角色連線成功的證據只證明當時連線和回覆差異，不能外推完整品質。正式問卷仍依學生自行確認完成，沒有外部回呼；兩組同時改共享資訊與回饋，不能分離估計两項效果。

改善提案：取得 Windows 真機後補原生重跑；若常部署，另規劃 Windows 自動檢查。這次未新增外部服務或產生 AI 測試費用。没有設定正式站或自動部署；GitHub 更新不等於正式網站已上線。
