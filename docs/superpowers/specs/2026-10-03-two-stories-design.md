# 蛋糕與第9杯飲料：核可設計

使用者於 2026-10-03 核可開始實作。依既有蛋糕流程加入飲料，畫面、時間與兩組介入保持相同。新學生首次登入依 1-1、1-2、2-1、2-2 循環，重登固定；不重分既有蛋糕學生。

## 資料與相容性
沿用現有 MySQL 與 students；新增研究安排、故事內容、故事回合及依回合保存的作答、對話、計時、草稿、觀看與事件表。舊 ck_* 學生紀錄不改寫，新表有明確 story 前綴。新舊使用同一套前端，舊單故事路徑保留。
研究安排記錄條件、順序、分配序號及時間。每位新學生有兩個不同 run_id，第一個完成後由使用者按鈕開始第二個，切換時核對舊 run_id，避免舊分頁把答案寫到新故事。所有資料讀寫以登入身分及 run_id 權限驗證。
故事內容以伺服器端 JSON 保存及版本化，公開回應以允許欄位清單組成，教師判斷、未來劇情及真相不提前送出。

## 流程
每故事：角色介紹 → 須知 → 每關影片 → 證詞 → 訊問 150 秒 → 分類與推理 240 秒 → 回饋；六關後保存完成。控制組不顯示分數解析，實驗組保留每關回饋。
故事之間顯示完成與下一故事名稱，使用者自行開始。第二個故事結束交由老師安排問卷；不新增問卷或外部串接，沿用學生自我確認完成後解鎖成果的契約。完整成果分故事顯示，不能合併稱為能力總分。
影片框架保留；缺少飲料影片時提示素材待補，不以蛋糕影片或文字閱讀冒充影片，也不讓学生略過。角色未有照片時以姓名識別，不使用蛋糕人物照片假冒。

2026-10-03 後續明確核可：逐人判定標籤優先，缺漏才用附錄，矛盾說明保留待老師修訂。第二關韓四城有瑕疵、夏五喬合理、唐六雅合理；第三關顧三曜依附錄有瑕疵。配分優先次序已定，不再等待確認。
